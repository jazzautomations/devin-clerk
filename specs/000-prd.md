# PRD — HackaHub

**Versão:** 1.0 · **Status:** vivo (atualizar a cada feature)
**Donos:** comunidade Hack Inova (jazz + César)

## 1. O problema

Cada hackathon vira um site novo do zero — "mesmas informações, só muda o lugar e a data". Inscrição via Google Forms mata a credibilidade (causou desconfiança real em Sorocaba — o evento parecia golpe). O legado das edições se perde: fotos, times campeões, projetos, slides e repos ficam espalhados ou somem.

## 2. A solução

**HackaHub = a rede social dos hackathons.** Um lugar só que é:

- **Infra de evento** — cada edição ganha página pública própria (`/h/[id]`) com inscrição em 1 clique. Nunca mais site novo, nunca mais Google Form.
- **Rede social** — feed público onde a comunidade posta demos, projetos e bastidores.
- **Arquivo vivo** — histórico completo de edições: times, projetos, repos, fotos, slides.
- **Radar** — hackathons BR+mundo raspados das fontes oficiais.
- **Identidade** — perfil público por membro com nível, badges e cartinhas colecionáveis de presença.

## 3. Personas

| Persona | O que faz aqui |
|---|---|
| Hacker/dev | Perfil, inscrição 1-clique, posta demos, coleciona cartas |
| Empreendedor | Acha co-founders, valida ideias no feed |
| Investidor | Scout: vê quem constrói e entrega |
| Professor/mentor | Reputação, mentoria nas edições |
| Marca/empresa | Desafios patrocinados, vaga/talento, sponsorship |
| Organizador | Cria sessões, gere inscritos, base de e-mail, arquivo |

## 5. Gamificação

- **XP**: inscrição +50, post +10, like recebido +5, perfil completo +25
- **Níveis**: novato(0) → hacker(50) → veterano(150) → elite(400) → lenda(1000)
- **8 badges** por estatística (pioneiro, identidade, debut, veterano, criador, influente, colecionador, organizador)
- **Cartinhas colecionáveis**: cada edição minta carta com serial incremental e raridade (comum/raro/épico/lendário). Edições Hack Inova = raridade curada; raspados = comum. Arte gerativa por hash.

## 6. Monetização (ordem de ataque)

1. **Desafios patrocinados** — empresa posta desafio/vaga pra quem se destaca
2. **Sponsorship** — slots de marca nas edições e no radar
3. **Talento** — recrutadores pagam acesso ao diretório curado
4. **Operação white-label** — rodar o hackathon da empresa na nossa infra
5. Infoprodutos — trilhas de preparação (MVP 24h, pitch, IA sob pressão)

## 7. Inventário honesto (estado real, não marketing)

**Funciona:** auth Clerk, perfil público, inscrição 1-clique com mint de carta, feed posts+likes, radar com ~100 eventos raspados (dedupe+classificação+expiração), admin completo (evento/inscritos/CSV/desafios), arquivo com times/projetos/materiais, **deploy tool** (repo → container → `/demo/id/` pela própria URL — provado E2E), desafios patrocinados, leaderboard por XP, gamificação XP/badges/cartas. Testes: ~120 unit/API/e2e.

**Quebrado/incompleto:**
- Scraper: Luma=0 (geogate), ETHGlobal=0 quando não há hack futuro (correto)
- Feed sem comentários (spec 011 em build), sem moderação
- Arquivo faltando dados reais das edições PUC/Anhembi (times/fotos)
- Sem "procuro time" (spec 012), sem notificações, sem talento/CRM

**Dívida técnica:** SQLite local não sobrevive a deploy serverless — Postgres/Supabase é blocker pra produção real. Bootstrap "1º membro = admin" é dev-only. Deploy tool roda código de terceiros sem sandbox real (mitigado por caps+TTL, ver spec 008).

## 7b. Aprendizado Colosseum (referência validada)

O funil deles é `hackathon → eternal → accelerator → portfolio`: o projeto
não morre na premiação, vira startup rastreada (`/companies/*`). Para nós:

1. `/p/[teamId]` — projeto vira cidadão de 1ª classe (página própria, não só linha no arquivo)
2. Countdown + "builders in the arena" na edição ao vivo — urgência, não página estática
3. "Cofounder matching" → nosso board "procuro time" (spec 012)
4. O arquivo alimenta o funil comercial: sponsors veem projetos entregues, investidores veem quem constrói
5. Deploy tool = nosso "unfair advantage" — eles não têm

## 8. Modelo de dados-alvo

`members(+xp, persona, headline, links)` · `hackathons(+source, ativo)` · `registrations` · `posts` · `likes` · `member_badges` · `cards` + `member_cards(serial)` · `subscribers` · **[a fazer]** `teams`, `projects`, `editions_assets(fotos/slides)`, `challenges(patrocinados)`, `sponsors`

## 9. Critérios de sucesso

- Qualquer hackathon da comunidade abre inscrição sem site novo nem Forms
- Membro novo vira perfil público com nível em <2 min
- Radar sempre tem ≥20 eventos reais e abertos, sem conferência infiltrada
- Toda edição encerrada vira arquivo com times/projetos/repos em ≤1 sessão de operação
- 0 regressão: `npm run test` + `test:e2e` verdes em todo PR

## 10. Processo (obrigatório daqui pra frente)

Spec Kit por feature (`specify → clarify → plan → tasks → implement`) com **TDD**: testes de aceitação BDD falhando antes do código, verde antes do commit. Gate no `PRODUCTION.md`.
